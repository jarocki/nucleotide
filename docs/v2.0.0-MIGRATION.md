# Migrating from 1.0.0 to 2.0.0

## What breaks

| Interface | 1.0.0 | 2.0.0 | Action |
|---|---|---|---|
| `lookup` output | 6 tab-separated columns | 7; column 7 is `weak`, `medium`, or `strong` | Update column parsing, or filter with `--min-quality` |
| Fingerprint YAML | — | new `low_signal` (bool) and `template_preference.weak_only_matches` (list) | Consumers should tolerate the new keys |
| Structural hash | computed from tool, CLI options, template set | for `low_signal` actors, also folds in `-rate-limit`, header names, scan strategy, User-Agent shapes, URI shapes | Re-fingerprint actors; 1.0.0 hashes and `actor-<hash>` ids for signal-poor actors do not carry over |
| `classify_event()` / `fingerprint()` | `matched_templates` | add `trustworthy_templates` and a `min_quality` keyword (default `medium`) | Attribution code should read `trustworthy_templates` |
| Lookup JSON | — | adds `snippet_quality` per template and top-level `snippet_quality_map` | A 1.0.0 lookup loads in 2.0.0 with every snippet treated as WEAK; a 2.0.0 lookup does not load in 1.0.0 |

## Steps

1. Install 2.0.0 (`git checkout v2.0.0 && pip install -e .`).
2. Rebuild the lookup: `nucleotide build --templates-dir <corpus> --out lookup.json`.
   The summary line now ends with `quality[strong=… medium=… weak=…]`.
3. Run `lookup` over a sample of your own traffic at `--min-quality medium`
   and at `--min-quality strong` and compare the UNIQUE rows before you
   alert on either. On the Log4Shell capture used for testing both gates
   produced 1 UNIQUE row; on galah, `medium` produced 18 and `strong` 10.
   Your traffic will differ.
4. Re-fingerprint any actors you track. Expect `low_signal: true` on actors
   with no MEDIUM-or-better hits and no Nuclei UA/OAST signal, and expect
   their hashes to change. `fingerprint --min-quality strong` is available
   if MEDIUM hits are too permissive for your traffic.
5. If you compare fingerprints, note that `compare` now caps the score at
   0.5 when both sides are `low_signal`.

## Rollback

Check out `d6dee5b` (1.0.0) and use a lookup built by 1.0.0. There is no
data migration to undo.
